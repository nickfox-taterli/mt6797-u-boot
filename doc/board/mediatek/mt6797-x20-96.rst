MediaTek X20-96 (MT6797)
========================

This port runs AArch32 SPL and AArch64 U-Boot proper on the 2 GiB X20-96
board. SPL initializes power, clocks, LPDDR3 and eMMC, then loads the
paired BL31/proper images. TF-A BL31 enters U-Boot at non-secure EL2, at
address 0x46000000. The verified X20 Preloader can also load proper as
an independent recovery path.

Supported functions are UART0 at 921600 baud, eMMC0 in 8-bit PIO mode at
25 MHz, GPT, ext4 loading, gzip-compressed ARM64 Linux via booti, and
PSCI reset. The fixed MSDC clock descriptions depend on the X20 Preloader
configuration (also used by SPL); they are not a replacement for an
MT6797 clock driver.

Build
-----

.. code-block:: console

   make O=build CROSS_COMPILE=aarch64-linux-gnu- mt6797_x20_96_defconfig
   make O=build CROSS_COMPILE=aarch64-linux-gnu- -j8

In the X20 workspace, ``mainline/x20-sbc/tools/build-x20-uboot.sh`` also
builds the matching BL31 and packages both images. Its output directory
defaults to ``out/u-boot-mt6797``.

Build SPL separately with the AArch32 toolchain:

.. code-block:: console

   make O=build-spl CROSS_COMPILE=arm-linux-gnueabi- mt6797_x20_96_spl_defconfig
   make O=build-spl CROSS_COMPILE=arm-linux-gnueabi- -j8 spl/u-boot-spl.bin

The workspace ``build-x20-spl.sh`` script additionally checks the actual
linked EMI record, SRAM/BSS/control-DT layout, GFH checksum and absent
training logs/binary libraries. Its BootROM download output is
``out/u-boot-spl-mt6797/u-boot-spl-gfh.bin``. The verified Preloader's
hardware C subset and frozen GPIO/EMI inputs are under
``arch/arm/mach-mediatek/mt6797/early``; see its README and IMPORTS.json.
SPL does not link SecLib, SecPlat, DaVerifyLib or PicachuLib.

The SRAM entry is 0x201000. After DRAM initialization and a small memory
check, SPL moves its stack and heap to DRAM. It locates ``lk`` and
``tee1`` by GPT name, validates their MTK headers and load bounds, and
uses the board's AArch32-to-AArch64 warm reset to BL31 at 0x101000.
The CPU0 reset vector register is 0x10220038. Training debug calls and
format strings are compiled out; normal SPL output has four stage lines.

For Boot1 deployment, preserve the board's existing 0x800-byte media
header and place the GFH image at offset 0x800. Upstream's complete
``u-boot-spl-mtk.bin`` uses a different media-prefix size; it is not the
direct Boot1 write input for the existing partition layout.

The existing Preloader requires the MTK LK partition wrapper, with the
image name ``lk`` and the extended v1 512-byte partition header. Upstream
mkimage's legacy LK prefix alone is insufficient for this configuration.
The workspace build script supplies these fields and checks the payload
and the 512 KiB partition limit. Do not write a raw ``u-boot.bin`` into
the lk partition.

BL31 must be built with ``X20_BL33_AARCH64=1`` and ``X20_WDT_FIQ=1``.
Besides selecting AArch64 EL2 for BL33, this mode performs the existing
one-time CPU rail initialization before entering U-Boot. The legacy
32-bit LK profile performs that initialization during its kernel-entry
SMC instead. Switching bootloaders therefore requires the matching tee1
image; the workspace deploy tool verifies and backs up both partitions.

Boot files
----------

The built-in environment loads these files from eMMC GPT partition 3:

* ``/boot/u-boot/Image.gz``
* ``/boot/u-boot/x20-96.dtb`` (the Linux board DTB, not U-Boot's control DT)

The default root PARTUUID is specific to the existing X20 installation.
Change ``bootargs`` for another partition layout. Environment changes
are volatile; persistent environment storage is intentionally disabled.
The autoboot delay is two seconds and the prompt is ``X20=>``.

U-Boot reserves the Preloader's top 384 KiB of DRAM and the existing
0x43f00000/4 KiB and 0x44600000/64 KiB firmware regions. It stops the
unused SCP and disables the inherited watchdog before interactive
operation, following the working LK handoff. Linux subsequently arms
its normal watchdog policy.

The old raw Linux bundle and minimal LK images remain recovery inputs.
This port does not provide USB, networking, display or TF-card support.
The SPL profile is for the unsecured X20 development board and does not
implement authenticated image loading for locked products.
